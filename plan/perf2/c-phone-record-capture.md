# Speed sweep C: phone recording, live caption, capture, import (2026-10-05)

Top 3 by severity:
1. C1 (high): right after Stop, `AssetMaterializer.capture` reads the whole recording (and every photo) into `Data` on the main actor and inserts it as an inline SwiftData blob.
2. C2 (med-high): `PhotoTextIndexer.run` and `AssetMaterializer.captureMissing` fetch the whole corpus on the main actor after every recording save, every CloudKit import burst, launch and (changed) foreground.
3. C3 (med-high): `VocabularyBooster.boost` decodes the entire audio file to a 16 kHz `[Float]` after every transcription when custom words exist (about 115 MB for 30 min, about 460 MB for 2 h), undoing FluidAudio's disk-backed path.

Static read only. Nothing here was measured. Anything not confirmed through the call chain is marked "suspect".

## 3. Checked, no finding

- Memory growth in a 30 min recording is bounded: `LiveCaptionEngine.streamBuffers` is trimmed at 25 s (hard cap 90 s, `Shared/Recording/LiveCaptionEngine.swift:82,157`), `committedChunks` holds text only, `RecordingLifecycleLog.mirror` is capped at 200 lines, `Meter` is fixed at 40 bars. Nothing leaked or unbounded found.
- Live caption cost control already exists: self-paced poll off measured snapshot cost, thermal stretching, early rotate when a snapshot passes 1.2 s (`LiveCaptionEngine.swift:339-345,390-398`). Auto-off defaults to 60 s.
- Live Activity pushes are throttled to 1.5 s with a 220-char tail (`RecordingActivityManager.swift:40,109-116,164-165`). Widgets use `policy: .never`; no timer refresh found.
- `ModelLoadStatus` quantises progress to 1% (`Services/ModelLoadStatus.swift:31-48`), so the record shell does not redraw per tick.
- Share-drain copies (`CaptureInboxDrainer`) and audio clip merges (`importAudioClipsAsync`, `appendAudio`) run detached, off the main actor.
- `LinkCard` HTML parsing and the shared audio/image copy tasks run off-main (Swift 5.9 mode: nonisolated async hops off the caller's actor).
- `PhotoTextIndexer` OCR itself is sequential on a utility queue (good); the cost is in finding what to scan (C2) and the full-bitmap decode (C8).
