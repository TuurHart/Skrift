# G: Mac background work (plumbing) — static read, 2026-10-05

1. HIGH — every reconcile sweep loads each processed memo's audio/photo blobs (`adoptLateDiarization` can never short-circuit for a monologue), plus 2 O(N) Memo lookups per row in `MacMemoAuthor.backfill/reflectTranscripts`.
2. HIGH — the sweep runs on the main actor and ingests new memos one by one (blob read, audio write, `save()` each); 200 arriving notes park the UI. Plus the open note's header recomputes a settings/ledger/Memo-fetch chain 3-4x per redraw.
3. MED — vault export and Process re-do work per run/per note: full vault tag scan before every Process, ledger + names.json decode per exported note, photo/audio byte-compare on every re-export even when the markdown is unchanged.

Scope: `Skrift_Native/SkriftDesktop/{Pipeline,App,Features/Shell}` and `Shared/{Export,Pipeline,Retrieval}`. Everything below was read from source and call chains; nothing was run or timed. "Suspect" marks anything where I did not follow the whole chain.

Context for the severities: `MemoCloudReconciler.reconcile()` (`App/MemoCloudReconciler+Wiring.swift:75`) is `@MainActor` and synchronous. It fires on launch (:55), on every app activation (:49-53), and ~1 s after every successful CloudKit import event (:39-46, coalesced by `reconcileSoon` :61-68). Memo has no `#Index` anywhere in the repo (`grep -rn "#Index"` is empty), and `Memo.id` is not unique (CloudKit), so every `Memo where id == x` fetch is a table scan.

## Checked, no finding (to save you re-checking)

- `BatchRunner.run` (`Pipeline/BatchManager/BatchRunner.swift`): no model loading per item. `ensureLoaded` is called once per run at `ProcessingCoordinator.swift:~187-195`. The three LLM calls per note (copy-edit, title, summary) each send the full transcript, which is engine-speed territory, not plumbing.
- `RunQueue` / `RunTurn`: pure value logic, Set-based, fine.
- `MemoCloudReconciler.sweep` itself builds `fileByID`/`fileByFilename` dictionaries up front and avoids per-memo fetches (good), the quadratic parts are in G2/G3's callers.
- `VaultStamp.locate` (`Shared/Export/VaultStamp.swift:140-153`) is still an uncapped vault enumeration (prior row #11: **still open, unchanged**) but only runs when a ledger path vanished (`VaultWrite.swift:248`). Rare.
- `NamesCloudSync.run` (`App/NamesCloudSync.swift:24-56`) does 2-3 names.json decodes + a carrier fetch per reconcile. Once per sweep, small. Falls under P10 (no cache).
- `MacCloudEditSync` is debounced 1.5 s (`App/MacCloudEditSync.swift:19`), fine.
