# Speed sweep E: search, semantic index, Connections, Journal/Review (2026-10-05)

Top 3 by severity:
1. E1: phone/iPad note search builds a full search snapshot (JSON decodes, string copies) for every note on every body pass and lowercases every transcript on every keystroke, with no debounce and no narrowing. E4 is the Mac twin: every non-matching note pays two uncached JSON decodes per keystroke.
2. E5/E7/E8: phone foreground index sweep does N SwiftData fetches on the main actor (E5); opening Connections or a note runs `ladderTitle()` for every note (5 regex passes over each full transcript, plus a JSON parse) on the main actor (E7); and the Connections panel runs the full name linker over every related note body (E8).
3. E10: first semantic search after every app resume pays a cold model load (device-logged 44-120 s), and the model is unloaded on every background.

Method: static read only, nothing measured. Everything below was confirmed by reading the call chain unless marked "suspect". The Memos list itself (row rendering, chips) is another reader's area; I only cover what search and Connections add to it.

## Notes on what looked fine (checked, no finding)

- `RetrievalMath.dot` is a plain loop (`EmbeddingEngine.swift:26-31`), 512 floats x about 10k rows is a few ms per query; not worth changing before E6b.
- `JournalIndexService.searchScores` and `refreshRelated` are debounced 250 ms and cancelled by newer queries (`+Derived.swift:124-146`); the exact list never waits on them.
