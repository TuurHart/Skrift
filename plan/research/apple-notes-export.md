# Apple Notes export for a batched import / skip / decline flow

Researched 2026-09-27, open web only, no project code read. Local checks were read-only against
`/System/Applications/Notes.app` on this Mac (macOS 26.6, build 25G72). No Apple Notes user data was opened.
Blocked hosts (HTTP 403): podfeet.com, appleinsider.com, forums.macrumors.com. Their claims appear below only
where a search snippet quoted them, and are marked as such.

## 1. Which export routes exist, what they produce, what they need

**What we asked:** which route gets several hundred flat notes out in batches, and at what permission cost.

**What others found:**
- **Built-in Markdown export (macOS 26 / iOS 26).** Mac: File > Export To/Export as > Markdown. iPhone: Share > Export as Markdown ([Apple Mac guide](https://support.apple.com/guide/notes/import-export-and-print-notes-not201900c07/mac), [Apple iPhone guide](https://support.apple.com/guide/iphone/export-or-print-notes-iphdf551cfa2/ios), [Apple 108306](https://support.apple.com/en-us/108306)). On the Mac you can Cmd+A in a folder and export every note at once. iOS exports one note at a time ([Bear migration FAQ](https://bear.app/faq/migrate-from-apple-notes/)). One commenter says multi-select arrived in 26.1 ([Tech2Geek](https://www.tech2geek.net/how-to-export-notes-to-markdown-in-macos-26-step-by-step-guide/)). Each note gets its own folder holding the `.md` and an `Attachments/` subfolder, even when it has no media (Podfeet via search snippet, blocked; [Tech2Geek](https://www.tech2geek.net/how-to-export-notes-to-markdown-in-macos-26-step-by-step-guide/)). If the importer is handed the `.md` alone, the media gets left behind ([Craft help](https://support.craft.do/en/import-and-export/import/apple-notes)). No permissions needed. Edit > Copy as Markdown also exists ([Apple Mac guide](https://support.apple.com/guide/notes/import-export-and-print-notes-not201900c07/mac)).
- **Export as PDF.** Same menu. Gives a visual copy that cannot be parsed back into structure ([Apple 108306](https://support.apple.com/en-us/108306), [dev.to TIL](https://dev.to/evanlin/til-exporting-from-apple-notes-185g)). "Open in Pages" is listed as an iPhone share option. What it keeps: not found.
- **Hidden "Export Archive…".** The string ships in Notes.app on macOS 26.6 (from reading `Contents/Resources/Localizable.loctable`, next to "Select accounts, folders, and notes you would like to export"). It is an undocumented interchange format behind `defaults write com.apple.Notes alexandria -bool YES`, tested only on macOS 12 ([zwaldowski/NotesArchive](https://github.com/zwaldowski/NotesArchive)). Whether it works on 26, and what it contains: unconfirmed.
- **Shortcuts.** "Find Notes" filters on name, body, folder, creation and modified date. Note actions return plain text only and cannot handle attachments ([MacStories](https://www.macstories.net/stories/shortcuts-rewind-working-with-apple-notes-part-1/)). On macOS 26 Notes also exposes intents named "Create Note from Markdown" and "Append Markdown to Note" (from reading `Localizable.loctable`). A Shortcuts-based bulk exporter writes HTML that points at attachments with `file:///` references ([Kylmakalle/apple-notes-exporter](https://github.com/Kylmakalle/apple-notes-exporter)).
- **AppleScript / JXA.** The Notes scripting dictionary on macOS 26.6 gives each note `id`, `name`, `body` (HTML), `plaintext`, `creation date`, `modification date`, `password protected`, `shared` and `container`. Attachments carry `id`, `content identifier`, `URL` and their own dates (from reading `sdef /System/Applications/Notes.app`). This route needs the Automation permission ([justinmitchel.com](https://justinmitchel.com/posts/sync-apple-notes-to-markdown/)). It is slow: about 1,600 notes take 30–50 min ([loran/AppleNotes-to-Obsidian](https://github.com/loran/AppleNotes-to-Obsidian)).
- **Reading `~/Library/Group Containers/group.com.apple.notes/NoteStore.sqlite` directly.** Note bodies are gzipped protobuf in `ZICNOTEDATA.ZDATA` ([Simon Willison](https://simonwillison.net/2021/Dec/9/notes-on-notesapp/)). Obsidian Importer asks the user to pick the `group.com.apple.notes` folder in an open panel ([Obsidian help](https://obsidian.md/help/import/apple-notes)). Other tools ask for Full Disk Access ([loran](https://github.com/loran/AppleNotes-to-Obsidian)). Since Sequoia, group containers are SIP-protected and other apps hit a consent prompt ([Apple forums 756701](https://developer.apple.com/forums/thread/756701), [Michael Tsai](https://mjtsai.com/blog/2024/09/11/group-container-names-in-sequoia/)). Whether a **sandboxed App Store app** can read the store with a user-picked folder or FDA: unconfirmed. Mac App Store exporters that keep dates and folders do exist ([Exporter](https://apps.apple.com/us/app/exporter/id1099120373), [Notes Exporter: Markdown Sync](https://apps.apple.com/us/app/notes-exporter-markdown-sync/id6741618455?mt=12)). How they get access: not found. Parsers: [apple_cloud_notes_parser](https://github.com/threeplanetssoftware/apple_cloud_notes_parser) (iOS 9–26, HTML/JSON/CSV), [apple-notes-parser](https://github.com/RhetTbull/apple-notes-parser) (Python), [kzaremski/apple-notes-exporter](https://github.com/kzaremski/apple-notes-exporter) (Swift app reading the DB, iCloud and On My Mac accounts only).
- **privacy.apple.com data copy.** Lossy: links are stripped to plain text and users report tables missing ([Apple Community](https://discussions.apple.com/thread/256188501)).

**Recommendation:** use the **built-in Markdown export, folder-at-a-time on the Mac**, as the user-facing route. It needs no permissions and is the route Bear and Craft now document. It carries no stable ID (see Q3). If decline-memory has to survive renames robustly, the only route with a real ID is reading NoteStore.sqlite.

**Our next step:** export one throwaway test note that holds every media type in Q2 via Markdown on macOS 26.6, and record the exact folder and file layout.

## 2. What survives, per media type

**What we asked:** what each route does to each kind of content.

**What others found** (MD = built-in Markdown, AS = AppleScript, DB = NoteStore.sqlite):
- **Text formatting.** MD keeps headings, lists, bold, italic and links. It drops highlight colours ([Gadget Hacks](https://apple.gadgethacks.com/how-to/how-to-import-and-export-markdown-in-apple-notes-on-ios-26/), [MacRumors](https://www.macrumors.com/how-to/ios-import-export-markdown-apple-notes/)). AS "silently destroys hyperlinks" in `body` ([gig3m/applenotes](https://github.com/gig3m/applenotes)).
- **Note-to-note links.** MD degrades them to plain text ([Gadget Hacks](https://apple.gadgethacks.com/how-to/how-to-import-and-export-markdown-in-apple-notes-on-ios-26/)). DB keeps them (Obsidian Importer supports the iOS 17 links: [Obsidian blog](https://obsidian.md/blog/apple-notes-export/)).
- **Rich link previews.** In the older HTML route they become plain links ([Bear FAQ](https://bear.app/faq/migrate-from-apple-notes/)). MD: unconfirmed.
- **Tables.** MD: "tables, footnotes, or diagrams may not render correctly" ([Apple World Today](https://appleworld.today/2026/03/how-to-import-and-export-markdown-files-with-macos-tahoe-notes/)). The exact output is unconfirmed. AS gives HTML, and complex tables convert imperfectly ([loran](https://github.com/loran/AppleNotes-to-Obsidian)). DB renders real tables ([apple_cloud_notes_parser](https://github.com/threeplanetssoftware/apple_cloud_notes_parser), [Obsidian help](https://obsidian.md/help/import/apple-notes)).
- **Checklists.** MD: not found. AS: plain text ([loran](https://github.com/loran/AppleNotes-to-Obsidian)). HTML route: plain bullets ([Bear FAQ](https://bear.app/faq/migrate-from-apple-notes/)). DB: kept ([apple_cloud_notes_parser](https://github.com/threeplanetssoftware/apple_cloud_notes_parser)). One pitfall: a checklist item that starts with a link loses its checkbox ([obsidian-importer #471](https://github.com/obsidianmd/obsidian-importer/issues/471)).
- **Drawings / sketches.** MD: "may exclude … handwritten notes, or embedded documents" ([Tech2Geek](https://www.tech2geek.net/how-to-export-notes-to-markdown-in-macos-26-step-by-step-guide/), unconfirmed first-hand). Shortcuts: not supported ([Kylmakalle](https://github.com/Kylmakalle/apple-notes-exporter)). DB: a PNG from `FallbackImages/<ZIDENTIFIER>/<generation>/FallbackImage.png`. A drawing never downloaded from iCloud is skipped (from reading the library source, [obsidian-importer `src/formats/apple-notes.ts`](https://raw.githubusercontent.com/obsidianmd/obsidian-importer/master/src/formats/apple-notes.ts)).
- **Scanned documents.** DB: older scans come out as uncropped image series, newer ones as cropped images, and scans edited on iOS 17+ as PDFs ([Obsidian help](https://obsidian.md/help/import/apple-notes)). MD: unconfirmed.
- **Images.** MD: files in `Attachments/`, linked rather than embedded (Podfeet snippet, blocked). AS: base64 inside the HTML `body`, no FDA needed ([loran](https://github.com/loran/AppleNotes-to-Obsidian)).
- **PDF / audio / video / other files.** MD: exported "including any attachments" ([Bear FAQ](https://bear.app/faq/migrate-from-apple-notes/)). AS: not in `body`, so you need a DB lookup plus FDA to copy them out of `Media/<id>/<generation>/<file>` ([loran](https://github.com/loran/AppleNotes-to-Obsidian); path from the obsidian-importer source above).
- **#tags and @mentions.** DB: exposed ([apple-notes-parser](https://github.com/RhetTbull/apple-notes-parser), [apple_cloud_notes_parser](https://github.com/threeplanetssoftware/apple_cloud_notes_parser)). MD: not found.
- **Locked notes.** DB: title, dates, UUID and folder stay readable, while the body and attachments are encrypted ([Ciofeca Forensics](https://www.ciofecaforensics.com/2020/07/31/apple-notes-revisited-encrypted-notes/), 2020 schema). The body can be decrypted with the note password, but not when the note uses the iOS 16+ device passcode ([apple_cloud_notes_parser](https://github.com/threeplanetssoftware/apple_cloud_notes_parser)). Obsidian skips locked notes ([Obsidian help](https://obsidian.md/help/import/apple-notes)). Shortcuts exports the title only ([Kylmakalle](https://github.com/Kylmakalle/apple-notes-exporter)). Locked notes cannot hold video, audio, PDF or file attachments (from reading Notes.app `Localizable.loctable`). MD on a locked note: not found.
- **Folders / smart folders.** MD keeps the folder you export from ([Bear FAQ](https://bear.app/faq/migrate-from-apple-notes/)). Obsidian filters smart folders out (obsidian-importer source above). This does not matter for one flat list.
- **Created / modified dates.** MD: no front matter or date metadata found. Whether file timestamps match the note's dates is unconfirmed. AS and DB have both dates. DB stores seconds since 2001 in `ZCREATIONDATE1`/`ZMODIFICATIONDATE1` ([jkeefe/notes-parser](https://github.com/jkeefe/notes-parser/blob/main/PROCESS_NOTES.md)). Obsidian falls back through `ZCREATIONDATE1/2/3` (obsidian-importer source above).

**Recommendation:** treat MD output as **text, images and files only**. Assume tables, checklists and drawings need checking per note until the test export in Q1 proves otherwise.

## 3. Stable identity across exports

**What we asked:** what lets the importer recognise the same note after its title or body changes.

**What others found:**
- **DB: `ZICCLOUDSYNCINGOBJECT.ZIDENTIFIER`**, a UUID that stays the same across iCloud-synced devices ([apple_cloud_notes_parser README](https://github.com/threeplanetssoftware/apple_cloud_notes_parser/blob/master/README.md), [gig3m/applenotes](https://github.com/gig3m/applenotes)). Obsidian Importer writes it into each imported note (`withSourceId(content, row.ZIDENTIFIER)`), uses it to find earlier imports, and skips a note when `appleNoteModTime <= existingFileModTime` (from reading the library source, [apple-notes.ts](https://raw.githubusercontent.com/obsidianmd/obsidian-importer/master/src/formats/apple-notes.ts)). No page directly states that it survives a title edit. That is strongly implied by it being the sync key, but unconfirmed. Whether it survives duplicating a note or moving it between accounts: not found.
- **AS: `id` = `x-coredata://…/ICNote/p170`.** This is a local Core Data row key and does not resolve on other devices ([gig3m/applenotes](https://github.com/gig3m/applenotes)). It is probably stable on one Mac, but that is unconfirmed. The deep link `notes://showNote?identifier=<ZIDENTIFIER>` uses the UUID (same source).
- **MD export: no ID found.** The filename is the title, so a rename changes it. A Shortcuts exporter ended up keying on creation date "to distinguish different notes with the same title" ([Kylmakalle](https://github.com/Kylmakalle/apple-notes-exporter)).

**Recommendation:** key the decline list on **`ZIDENTIFIER`** if the app reads the store. If the app stays on MD export, no stable key exists. Key on creation date only if the test export shows it is carried, and add a body/attachment fingerprint as a secondary match. Expect renames to be caught only if the body barely changed.

**Our next step:** in the test export, rename the test note, export again, and diff both folders' `.md` and the file creation/modification times (`stat -f '%SB %Sm'`).

## 4. Pitfalls others hit

- **Attachments mixed up or dumped in the vault root, uncropped images, and "Previews/<UUID>.jpeg" failures** when the `Previews` folder is empty ([obsidian-importer #393](https://github.com/obsidianmd/obsidian-importer/issues/393), open, no fix).
- **Drawings:** "(error reading attachment)" ([#134](https://github.com/obsidianmd/obsidian-importer/issues/134), fixed by PR #137). A crash reading `ZIDENTIFIER` on notes with pencil drawings ([#218](https://github.com/obsidianmd/obsidian-importer/issues/218), closed with no fix shown).
- **Files that exist only in iCloud** are not on disk, so they get skipped (the `reasonNotDownloaded` path in the importer source above).
- **Extensionless UUID attachment names, attachments linked rather than embedded, `#gift ideas` cut to `#gift`, text like `#s` wrongly treated as a tag, numeric tags, slashes removed from titles, unescaped `[ ]`** ([#471](https://github.com/obsidianmd/obsidian-importer/issues/471)).
- **Dates:** dedupe that relies on creation dates re-imports when `ZCREATIONDATE` is missing, and invalid timestamps fall back to "now" (importer source above). The Evernote importer still fails to set some dates ([#286](https://github.com/obsidianmd/obsidian-importer/issues/286)). Date loss in Shortcuts-to-Notion migrations: not found with a source.
- **Reading a live DB:** Obsidian copies `NoteStore.sqlite` together with its `-wal` and `-shm` files before reading (importer source above).
- **Markdown export layout:** importing a loose `.md` leaves the media behind ([Craft](https://support.craft.do/en/import-and-export/import/apple-notes)). Bear says to move the export into a fresh folder so it does not import stray files ([Bear FAQ](https://bear.app/faq/migrate-from-apple-notes/)).

**Recommendation:** import from the **whole per-note export folder**, never from a loose `.md`. Resolve attachments per note, and flag any note whose referenced attachment is missing instead of importing it silently.
