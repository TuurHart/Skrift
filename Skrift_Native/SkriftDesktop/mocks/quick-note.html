The one question

On the phone, does New Note sit next to the red mic at the bottom, or up in the header beside Select?

Choices to overrule

PICK 1 · PHONE PLACEMENT

New Note is a 52pt ✎ button to the left of the red mic, in the bottom row you reach with your thumb.

Today the phone has no New Note button at all (only the iPad has ✎, in its verb row). The header already holds Select, Import, Scan and Filter. With a book playing, the book pill takes the left of the row: pill · ✎ · mic.

PICK 2 · WHERE THE CURSOR LANDS

The cursor lands in the body. The title stays empty and shows the faint "Add a title" prompt.

You start with the thought, not with naming it. The list row falls back to the first line when there's no title, as it does today.

PICK 3 · HOW THE DISCARD FEELS

The discard is silent: no toast, no undo. A note counts as empty when it has no title text, no body text and no photo at the moment you leave, so typing something and deleting it all also discards.

D91 says "untouched". This reads it as "empty when you leave" rather than "no key was ever pressed". Build note: create the Memo on the first keystroke, not on the tap, so an empty note never syncs to the Mac. Today Memo.newTyped saves on the tap.

PICK 4 · A SECOND BUTTON, NOT A CHANGED ONE

New Note is its own control and widget next to the existing Record (❝) one, with the same ✎ glyph the app uses. Siri phrase: "New note in Skrift".

The Lock Screen corner slot and Control Center both take one Control; you place Record and New Note separately. Plain "new note" goes to Apple Notes, so the phrase has to name Skrift.

What this mocks

C112
New Note from the app, the Lock Screen / Control Center widget and Siri opens an empty note, keyboard up, in under a second.
C114
The app opens into the list, New Note one tap away. Widget and Siri push the note on top of the list, so Back lands in the list.
C43 / D91
An untouched empty typed note is discarded when you leave it and never listed.
